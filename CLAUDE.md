# alpinelib

Core reusable library for genre-agnostic Unity game development. Provides reusable systems (animation, networking, editor tooling, build pipelining, etc.) to make bootstrapping and developing Unity games easier and more consistent. No limits on scope of what it provides.

## Git Conventions

- **Never** use `Co-authored-by` trailers.
- No commit message bodies unless explicitly requested — subject line only.
- Commit subjects are short and concise.
- Always prefix the subject with a single word (no scope brackets). Allowed prefixes: `feat`, `fix`, `chore`, `docs`, `refactor`.
- Never undo changes to split work across commits. Unrelated changes may share a commit as long as each commit is still a logical group.

## Code Style (C#)

- **Access modifiers** — every class member declares one explicitly; `private` is written out, never implied.
- **One class per file** — file name matches the class name.
- **Class-file helpers** — helpers in class-bearing files live as methods on the class: `private` for internal use, `public static` if consumed externally. No loose module-level utility sprawl.
- **Guard clauses** — invert conditions and early-return; nesting depth ≤ 2. Extract inner loops/branches into helpers rather than deep-nesting.
- **Naming** — descriptive variables; expand lambda/LINQ params (`(t)` → `(task)`) and loop counters (`index` not `i`).
- **Inline functions** — single-statement lambdas may be inlined; multi-statement handlers must be extracted to a named method.

## Netcode Roadmap

- **Server-side collision (exists)**: `Netcode/Collision/` carries a real, engine-free collision world — planes, boxes, spheres and capsules in a 2m XZ grid, plus translation-only movers whose pose is a pure function of the sim tick. Scenes are authored in Unity (`NetStaticGeometry`, `NetMover`), baked by `AlpineLib/Editor/Export Scene Geometry` into a `.geo` blob the dedicated server loads from `config/geometry/` and a `SceneGeometryAsset` the client resolves through a `SceneGeometryRegistry`. Both ends step the same `PawnMotor` against the same bytes, so the simulation owns Y: ramps, walls, step-ups and platform rides all resolve identically on server and predicting client.
- **Owner movement architecture (current)**: `Actor` is a fixed-step kinematic capsule motor (`Runtime/Actors/Locomotion/CapsuleMotor`, own accumulator at `ActorExecutionOrder.Motor`, render pose interpolated between steps) — no `CharacterController`; the pawn is a `CapsuleCollider` on a kinematic `Rigidbody` and the motor sweeps PhysX at explicit poses through `ICapsuleCollisionQuery`, which is the seam an engine-free backend would fill. Its state is carrier-local (`MotorState.CarrierRoot`, the kinematic body the ground probe found) and the transform is parented under that carrier, so a deck's motion is never swept; `PhysicsTransformSync` syncs physics once per frame after carriers have moved. `NetActorSync` samples the motor, settles the reported carrier through `CarrierSettlePolicy` (immediate between frames moving apart, a dwell between frames moving together), and applies corrections through `Actor.Nudge`/`Actor.PlaceAt`. `PawnMotor` prediction (server authority) still exists alongside, unused by All Aboard.
- **Sessions and the dedicated server (landed)**: `Server~/AlpineLib.Server` is a net10.0 host a game builds its own executable on — `AlpineServerHost` (Generic Host, `--port/--config/--idle-exit-seconds/--max-sessions`, one machine-readable `[ready] port=N` line, idle shutdown), `GameLoopService` at a fixed tick with a `GameThreadInbox` for off-thread work, `SessionRegistry`/`SessionEntry` per live session, and `ISessionModuleFactory`/`ISessionModule` as the game's seam. `SessionConfigExporter` flattens the client's own `SessionConfig` asset into the JSON it boots from; `LocalServerLauncher` plus `ServerBundleConfig`/`ServerBundleBuildStep` mean a player who hosts starts that same binary out of a `Server/` folder beside the build and then connects to it as an ordinary client. There is no listen-server path.
- **Look pitch (landed)**: `Actor.LookPitch` is the one place a body's vertical look lives — a player's controller copies its camera rig, `NetController` copies the wire — and `PawnState.LookPitchDegrees` replicates it as an appended sbyte (protocol version 6). `LookPoseModifier` on a `PoseModifierStack` bends the spine to it and feeds the first-person eye through `ICameraEyeModel`. Anything that rebuilds a `PawnState` copies the struct and changes fields rather than constructing positionally, so the next appended field is not dropped.
- **Carrier-relative pawn state (landed)**: `PawnState.CarrierId` names the deck a pawn stands on, and `NetCarrier`/`NetCarrierRegistry`/`NetCarrierFrame` convert between that frame and the world. A rider on a 30 m/s train is validated, interpolated and corrected on the metre a second it is responsible for rather than the forty it is carried through. The reported carrier is hysteresis-damped (`NetCarrier.SourceHysteresisSeconds`), so a body standing across a coupler gap does not change frames every tick.
- **State channel and claims (landed)**: `ServerStateChannel<T>`/`ClientStateChannel<T>` replicate game-owned records that are not pawns — keyframe to a joiner, deltas to everyone else, chunked to a datagram — under an id from the game band; `ServerClaimRegistry`/`ClientClaims` arbitrate exclusive slots (one driver per lever) with the server owning the map and clients never assuming a grant. `MessageIdBudget` is what stops a game authoring an id the library already speaks.
- **Known gaps** (found by the consuming game, not yet fixed here): `SessionEntry` builds its `ServerClaimRegistry` before the module exists, so a game cannot supply the `isSlotValid` predicate and must release a bad claim *after* it has been granted and broadcast; `ISessionModule` has no post-construction hook; a refused claim is answered with silence rather than a denial, so clients fall back to a timeout; `SessionService`/`NetworkService` swap `Client`/`Replication`/`Claims` wholesale with no event, leaving consumers to reference-compare every frame; `ClientClaims` raises `OnClaimChanged` and `OnClaimLost` for the same transition; `NetEntitySpawner` does not clear the announced player when an owned pawn despawns mid-session; multi-chunk state-channel publishes should be `Unreliable` rather than `UnreliableSequenced`; `ServerRuntimeOptions.ResolvePath` does not normalise.
- **Single-sim promotion (unblocked, still out of scope)**: the prerequisite this was waiting on — real server-side ground data — is met, so promoting `PawnMotor` to the single simulation for networked owned pawns is now a scheduling question rather than a blocked one. The shape is unchanged: fixed-step sim + render interpolation, Actor demoted to presentation, `CharacterController` used only for collision resolution inside the step, removing the dual-model alignment burden entirely. Deliberately not attempted in this pass; treat it as the next architectural move, not an incidental refactor.
